# 技术架构

## 双层模型

```
Agent定义层（简洁、声明式、面向业务）
  Agent = 指令 + 工具 + 约束
  可视化 = AI通过render_visual工具自主生成

运行时基座层（可靠、工程化、面向运维）
  LLM网关: 多模型 / 限流 / 成本记录 / 降级
  工具执行器: 超时 / 重试 / 沙箱
  审计日志: SHA-256哈希链
  指标收集: 成本 / Token / 延迟
```

## 核心引擎

### SessionEngine（产品核心）

对话式任务引擎。用户说自然语言 → AI 自主规划执行 → 流式返回文本+可视化+工具调用结果。

关键设计：
- 系统提示词内含可视化哲学，AI主动调用`render_visual`工具
- 每轮对话携带已生成可视化的摘要，支持追问式交互
- SSE流式推送：thinking → text → visual → tool_call → done

### AgentRuntime（执行引擎）

ReAct循环 + 三重约束检查（成本/轮次/超时） + 审批拦截 + Handoff转交。

### LLMGateway（基础设施）

统一接入Anthropic和OpenAI。令牌桶限流、成本估算（6种模型价格表）、故障自动降级。

### ToolExecutor（基础设施）

支持HTTP/SQL/Python/Retrieval/Mock五种执行方式。统一的超时控制和指数退避重试。

## 数据模型

| 模型 | 用途 |
|------|------|
| Connection | 数据源连接（OpenAPI/数据库/文档） |
| Tool | Agent可用的工具（自动从Connection生成） |
| Agent | Agent定义（指令+工具+约束） |
| Workflow | 内部工作流（DAG结构，非用户界面） |
| WorkflowRun | 运行实例 |
| NodeExecution | 节点执行记录 |

## API设计原则

- **Session API是主接口**：`/api/sessions/chat` 是产品的入口
- 其他API（connections/tools/agents）是配置管理，非日常使用
- Session用SSE流式推送，其他用标准REST
