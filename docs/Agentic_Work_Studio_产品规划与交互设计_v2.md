# Agentic Work Studio — 体系化产品规划与功能交互设计 v2

> 本文档基于"对话是主体、可视化是AI思维外化"的产品哲学，结合当前已落地的代码（studio/ 2800行后端 + web/ 1100行前端），做一份可直接执行的产品规划和交互设计。

---

## 一、产品重新定义

### 1.1 一句话

**Agentic Work Studio 是一个"说人话就能干活"的 AI 工作台——用户描述业务意图，AI 自主拆解执行，过程中用动态图形帮用户思考和决策。**

### 1.2 它不是什么

| 它不是 | 因为 |
|--------|------|
| 工作流编辑器（Dify/n8n/Coze） | 用户不画流程图。AI自己规划执行路径 |
| Chatbot搭建平台 | 不是做一个聊天机器人给终端客户用。是给业务人员自己用的工作台 |
| BI仪表盘（Tableau/Metabase） | 不是看固定报表。图形是AI根据当前问题动态生成的思维工具 |
| Agent开发框架（LangChain/CrewAI） | 不面向开发者写代码。面向业务人员说自然语言 |

### 1.3 它是什么——三层价值

```
┌─────────────────────────────────────────────────┐
│  第三层：决策增强                                  │
│  AI帮我看到我看不到的：结构、趋势、关联、风险      │
│  （动态可视化的价值）                              │
├─────────────────────────────────────────────────┤
│  第二层：工作自动化                                │
│  AI帮我做我不想做的：查数据、算指标、写报告        │
│  （Agent执行的价值）                              │
├─────────────────────────────────────────────────┤
│  第一层：意图理解                                  │
│  AI听懂我说的：业务语言 → 执行步骤                │
│  （LLM理解的价值）                                │
└─────────────────────────────────────────────────┘
```

## 二、目标用户与场景矩阵

### 2.1 核心用户画像

**主力用户：业务分析师 / 运营负责人 / 项目经理**

共同特征：
- 每天需要处理大量信息、做分析、出决策
- 不会写代码，但能清楚描述业务需求
- 习惯用 Excel/PPT/飞书文档 工作
- 痛点：重复性分析、信息过载、跨系统查数据

### 2.2 五个核心场景

| 场景 | 用户说的话 | AI做的事 | AI生成的可视化 |
|------|-----------|---------|---------------|
| **数据洞察** | "分析上月销售数据，看看哪些产品掉了" | 查数据库→计算同比环比→定位异常 | 柱状图(趋势) → 热力图(品类对比) → 决策树(建议行动) |
| **竞品调研** | "帮我整理XX行业主要玩家的产品对比" | 搜信息→提取结构→对比分析 | 表格(功能对比) → 网络图(竞争关系) → 雷达图(优劣势) |
| **方案策划** | "策划一个双11促销活动方案" | 分析历史→生成框架→细化计划 | 思维导图(方案全景) → 时间线(排期) → 预算表格 |
| **问题诊断** | "最近客户投诉变多了，帮我找原因" | 拉投诉数据→分类统计→根因分析 | 树形图(投诉分类) → 趋势线(时间变化) → 因果网络(根因) |
| **报告生成** | "写一份本季度的业务review" | 汇总数据→提炼结论→生成图表 | KPI卡片(核心指标) → 对比柱状图 → 行动项表格 |

### 2.3 场景到可视化的映射逻辑

AI不是随机选图形，而是遵循**思维辅助逻辑**：

```
用户意图          →  需要辅助的思维类型     →  最佳可视化形态
─────────────────────────────────────────────────────────────
"看全貌"          →  结构化思维              →  思维导图 / 树形图
"看趋势"          →  时序思维                →  时间线 / 折线图
"做对比"          →  比较思维                →  表格 / 柱状图 / 雷达图
"找关联"          →  关系思维                →  网络图 / 因果图
"做选择"          →  决策思维                →  决策树 / 权衡矩阵
"看占比"          →  构成思维                →  饼图 / 堆叠柱状图
"看数字"          →  量化思维                →  KPI卡片 / 仪表盘
"理步骤"          →  流程思维                →  流程图 / 甘特图
"找问题"          →  诊断思维                →  根因树 / 漏斗图
```

**关键设计原则**：可视化的选择不是基于"数据类型"（这是BI的逻辑），而是基于"用户需要什么样的思维辅助"（这是AI工作台的逻辑）。

#### 3.2.2 对话区核心交互

**五种消息类型**：

| 类型 | 视觉表现 | 说明 |
|------|---------|------|
| **用户消息** | 右对齐蓝色气泡 | 用户的自然语言输入 |
| **AI文本** | 左对齐灰色气泡 | AI的分析说明、总结、建议 |
| **工具调用** | 左对齐绿色小条 | `🔧 查询投诉数据库... → 847条` |
| **审批卡片** | 内嵌卡片+按钮 | `⚠️ 需要确认：发送邮件给张总？ [确认] [拒绝]` |
| **引导提示** | 浅色提示气泡 | `💡 你可以说："展开产品质量类""对比一下各区域"` |

**追问式交互**（核心差异化体验）：

```
用户看到右侧的思维导图后:
  👤 "产品质量那个分支展开看看"
  → AI理解这是对可视化的追问
  → 重新聚焦到"产品质量"子类
  → 右侧生成：
     1. 产品质量投诉明细表格（新可视化）
     2. 质量问题关联的供应商网络图（新可视化）

用户看到趋势图后:
  👤 "3月份那个高峰是怎么回事"
  → AI理解这是对图表某个数据点的追问
  → 定位到3月数据，做归因分析
  → 右侧生成：3月投诉根因饼图
```

这就是"用户对着图说话"的交互模式——**可视化不是终点，是新一轮对话的起点**。

## 四、可视化语言体系

### 4.1 十种基础图形及其思维用途

| # | 图形类型 | 代码标识 | 思维用途 | 典型场景 |
|---|---------|----------|---------|---------|
| 1 | **思维导图** | `mindmap` | 看全貌、理结构 | 问题分类、方案框架、知识体系 |
| 2 | **树形图** | `tree` | 看层级、看分解 | 组织架构、成本分解、任务拆解 |
| 3 | **流程图** | `flowchart` | 理步骤、看逻辑 | 业务流程、审批链路、因果链 |
| 4 | **关系网络** | `network` | 找关联、看影响 | 利益相关方、根因关联、竞争格局 |
| 5 | **时间线** | `timeline` | 看趋势、理顺序 | 事件演变、项目排期、历史脉络 |
| 6 | **柱状图** | `bar_chart` | 做对比、看差异 | 业绩对比、分类统计、同比环比 |
| 7 | **饼图** | `pie_chart` | 看占比、看构成 | 费用构成、市场份额、问题分布 |
| 8 | **数据表** | `table` | 看明细、做比较 | 功能对比、数据明细、排名榜单 |
| 9 | **指标卡片** | `metric_cards` | 看数字、看状态 | KPI总览、实时指标、健康度 |
| 10 | **决策树** | `decision_tree` | 做选择、评权衡 | 方案评估、风险评估、条件分支 |

### 4.2 图形组合模式

复杂场景中，AI会生成多个图形来**引导思维的逐步深入**：

**模式一：全景 → 聚焦 → 行动**
```
思维导图（看全貌） → 柱状图（看重点） → 表格（看细节）→ 决策树（做选择）
```

**模式二：数据 → 洞察 → 因果**
```
指标卡片（看状态） → 趋势图（找异常） → 因果网络（找原因）
```

**模式三：现状 → 目标 → 路径**
```
指标卡片（现在在哪） → 对比图（差距多大） → 时间线（怎么到达）
```

### 4.3 可视化交互规则

| 规则 | 说明 |
|------|------|
| **AI主动生成** | AI判断需要视觉辅助时自动生成，不需要用户要求 |
| **带说明文字** | 每个图形都带一句话说明为什么生成这个图 |
| **可追问** | 用户可以对着图的任意部分追问 |
| **可导出** | 每个图形可复制数据、导出图片 |
| **上下文连贯** | 后续图形承接前面的分析脉络，不是孤立的 |
| **不阻塞对话** | 图形出现在右侧面板，不打断左侧对话流 |

### Phase 1：可用（4周）

**目标**：一个人从"说需求"到"看到结果"的完整体验跑通。

| 交付物 | 说明 | 已有基础 |

### Phase 2：好用（4周）

**目标**：接入真实数据源，Agent能调用真实API/数据库。

| 交付物 | 说明 |
|--------|------|
| OpenAPI导入 | 上传Swagger自动注册工具 |
| 数据库查询工具 | SQL执行器对接真实数据库 |
| 多会话管理 | 会话列表、历史恢复、会话搜索 |

| 追问式交互 | 点击图形元素→自动追问 |
| 成本追踪 | 每次会话的Token/成本实时显示 |

**验收标准**：接入客户真实数据库 → 用户问业务问题 → AI查真实数据 → 生成有意义的分析图表。

### Phase 3：商用（4周）

**目标**：可以交付给付费客户使用。

| 交付物 | 说明 |
|--------|------|
| 预设Agent套件 | 数据分析师/报告撰写员/调研员 |
| 人工审批流 | 高风险操作内嵌审批卡片 |
| Measure仪表盘 | ROI证明：节省时间/成本对比 |
| 导出能力 | 图表导出PNG/SVG，数据导出Excel |
| 多用户 | 账户体系、权限隔离 |
| 部署方案 | Docker一键部署 |

**验收标准**：客户部署后，业务人员日常使用，Measure仪表盘显示正向ROI。

### Phase 4：规模化（持续迭代）

| 方向 | 说明 |

| 生态 | 工具市场、Agent市场、模板市场 |

## 七、设计语言原则

### 7.1 视觉风格

| 元素 | 规则 |
|------|------|
| 主色调 | 蓝色系(#1890ff)——专业、可信赖 |
| 可视化色板 | 8色标准色板——语义一致、不刺眼 |
| 字体 | 系统默认字体——加载快、一致性好 |
| 卡片圆角 | 8px——现代感但不花哨 |
| 间距 | 16px基准——呼吸感 |

### 7.2 交互原则

| 原则 | 表现 |
|------|------|
| **对话优先** | 一切从一个输入框开始，不需要先配置 |
| **零前置步骤** | 新用户首次使用就能在Workbench对话（用预设Agent+Mock数据） |
| **渐进展开** | 先看到结果，想深入再追问，想配置再去设置 |
| **可视化不阻塞** | 图形在右侧面板静默出现，不打断对话流 |
| **成本透明** | 随时能看到花了多少钱，心里有底 |

### 7.3 文案原则

| 场景 | 文案风格 |
|------|---------|
| AI回复 | 简洁直接，先说结论再说过程，用"我"自称 |
| 可视化标题 | 说明"看什么"而非"这是什么图"（"投诉按类别分布" 而非 "饼图"） |
| 引导提示 | 给出具体的追问示例（"你可以说：展开产品质量类"） |
| 错误提示 | 说明影响+给出行动（"数据库连接超时，正在重试…"） |
