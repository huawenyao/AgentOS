# EFIAgent 供应链协作能力开发计划

版本: v1.0
日期: 2025-08-31
作者: EFIAgent 团队

## 1. 背景与目标
在现有协作平台中已内置“数据分析”和“工作流自动化”等任务分解规则，但缺少典型企业级场景“供应链优化”的一站式支持。本计划旨在：
- 为协作平台新增“供应链（supply_chain）”任务分解规则，覆盖从需求预测到库存计划、采购、生产排程、物流配送与异常监控的端到端流程。
- 无新增第三方依赖，复用现有架构、能力调度与执行机制。
- 在示例中提供可运行的供应链演示路径，便于团队与用户验证。

## 2. 范围与不在范围
- 在范围：
  - 新增供应链任务类型与分解规则。
  - 在示例中新增供应链演示调用，确保可运行。
  - 可选：为 ExecutionAgent 注册若干“供应链工具”占位实现（便于后续迭代替换为真实算法）。
  - 审计与评审流程对供应链任务的轻量校验规则与结果入库（沿用现有机制）。
- 不在范围：
  - 高精度优化算法（如商用求解器、复杂路线规划器）接入。
  - 新的数据存储或外部服务接入。

## 3. 受影响的模块与文件
- 任务规划与分解
  - efiagent/core/collaboration_platform.py：TaskPlanner._register_default_decomposition_rules、decompose_task、create_task_plan、generate_execution_plan。
- 执行智能体与工具
  - efiagent/agent/execution_agent.py：ToolRegistry 与 _register_built_in_tools，新增供应链相关工具（可选）。
- 示例
  - examples/collaboration_platform_example.py：新增供应链演示方法并纳入完整示例流程。
- 审计与评审（沿用现有结构，按需补充规则）
  - efiagent/agent/audit_agent.py：按 supply_chain 任务类型扩展规则模板（门禁、结果一致性检查）。
  - efiagent/agent/review_agent.py：利用 _quick_validation、_store_review_result、_start_correction_workflow 增强供应链任务结果校验。

## 4. 设计方案
### 4.1 供应链任务分解规则
在 TaskPlanner 中新增 supply_chain_decomposition，输出子任务（按依赖顺序）：
1) demand_forecasting（需求预测）
2) inventory_planning（库存计划）
3) procurement_planning（采购计划）
4) production_scheduling（生产排程）
5) logistics_distribution（物流配送）
6) exception_monitoring（异常监控）

每个子任务包含：
- task_type：与子领域一致的类型名。
- parameters：传入 horizon、method、lead_time、service_level、suppliers、capacity 等关键参数。
- required_capabilities：与平台现有能力体系对齐，如 time_series_forecasting、inventory_optimization、supplier_management、production_scheduling、route_planning、anomaly_detection 等。

在 _register_default_decomposition_rules 中注册：self.decomposition_rules["supply_chain"] = supply_chain_decomposition。

### 4.2 示例扩展
在 CollaborationPlatformExample 中新增“供应链演示”方法：
- 构造 requirements，其中包含 task_type="supply_chain" 与示例参数（forecast_horizon、lead_time、suppliers、capacity、vehicles 等）。
- 调用 platform.create_task_plan 与 execute_task_plan，打印分解结果、依赖与分配情况。
- 将该演示纳入 run_complete_example 的执行序列中（在不影响现有示例的情况下）。

### 4.3 执行工具（可选，占位实现）
在 ExecutionAgent._register_built_in_tools 中按需注册以下工具的占位实现（仅用于演示）：
- forecast_moving_average：简单移动平均预测。
- optimize_inventory_eoq：EOQ 粗略计算与安全库存建议。
- select_supplier：基于质量/成本/交期的简单打分选择。
- schedule_production：EDD 或 FIFO 简单排程。
- plan_routes：贪心/最近邻近似的路线规划占位实现。

所有工具添加清晰的函数注释，后续可替换为专业算法模块。

### 4.4 审计与评审
- 审计（AuditAgent）：
  - 计划审核：检查供应链任务是否齐全（预测→库存→采购→生产→物流→监控）、关键参数是否存在、依赖是否有环。
  - 执行审核：检查各阶段输出的基本一致性与约束（如非负数量、时序合理）。
- 评审（ReviewAgent）：
  - _quick_validation：校验预测结果长度与 horizon 一致、数量非负、订单/排产/路线结构完整。
  - 失败时 _store_review_result 入库，_start_correction_workflow 触发：
    - 规则缺失→重规划；
    - 数据缺失→数据补全请求；
    - 语义不清→澄清回合。

## 5. 工作分解与里程碑
- M1（第1-2天）：
  - 新增 supply_chain_decomposition 并注册到 TaskPlanner。
  - 本地运行 DAG 依赖检查，确保无循环，生成阶段正确。
- M2（第3-4天）：
  - 示例新增供应链演示方法，集成到 run_complete_example。
  - 打印任务分解、依赖、执行分配信息，确保可执行。
- M3（第5-6天，可选）：
  - 在 ExecutionAgent 注册供应链工具占位实现，完善函数注释与基本输入输出校验。
- M4（第7-8天）：
  - 审计与评审对 supply_chain 的轻量规则接入，确保失败路径可复盘与纠错。
- M5（第9-10天）：
  - 测试与稳定性：新增/完善单元测试与集成测试，整理文档与示例输出。

## 6. 测试计划
- 单元测试：
  - 任务分解数量与顺序、依赖正确性、参数透传、无环 DAG 校验。
- 集成测试：
  - 示例一键运行通过，任务分配成功；
  - 审计报告能够生成，评审发现问题时可触发纠错流程；
  - 执行阶段工具（若开启）输入输出结构符合预期。

## 7. 验收标准
- [ ] 指定 task_type="supply_chain" 时，能够生成包含 6 个阶段的任务计划且依赖正确无循环。
- [ ] 示例程序可在 Windows + Python 3.11.2 环境下通过 PowerShell 运行并输出供应链分解与执行启动日志。
- [ ] 无新增第三方依赖，CI 能正常通过。
- [ ] 代码中新增/修改的函数均包含必要注释与日志。
- [ ] 审计/评审能对常见输入异常给出明确提示或纠错动作。

## 8. 运行说明（本地）
- 环境：
  - Windows + PowerShell，Python 3.11.2。
- 步骤：
  1) 进入项目根目录。
  2) 运行示例：`python examples/collaboration_platform_example.py`
  3) 观察控制台输出：任务分解、依赖、任务分配、性能统计与健康检查。

## 9. 风险与缓解
- 风险：供应链任务链较长，若参数不全可能导致执行失败。
  - 缓解：示例参数提供默认值；在审计与评审阶段做前置校验并给出纠错建议。
- 风险：工具占位实现与真实算法存在偏差。
  - 缓解：通过函数注释与清晰接口定义确保后续替换成本低。

## 10. 后续迭代方向
- 接入更强的预测与优化算法（时序模型、路线规划求解器等）。
- 与外部 ERP/WMS/TMS 系统对接，形成闭环执行与反馈。
- 更细粒度的风险预警与供应中断自愈策略。

## 11. 扩展方向：构建基于“超级上下文”的通用业务智能平台 v2.0

### 11.1 核心理念

在 v1.0 供应链能力的基础上，下一阶段的核心目标是将 EFIAgent 从一个面向特定领域（如供应链）的协作平台，升级为一个**通用业务智能平台**。其核心思想是：将企业内所有传统业务系统、API、数据、流程、规范和最佳实践，统一视为一个动态更新的“**超级上下文（Super Context）**”。

Agent 不再仅仅是任务的执行者，而是成为一个能够**自主理解业务、动态生成策略、并安全调用内外部能力**的“企业大脑”。用户通过自然语言提出业务目标（Intent），平台即可自动完成从“目标理解”到“策略生成”再到“自动化执行与反馈”的全链路闭环。

### 11.2 方法论与架构升级

为实现此目标，需在现有架构上进行以下升级，将“数据驱动”与“AI驱动”深度融合：

| **核心环节** | **v1.0 (供应链)** | **v2.0 (通用平台)** | **关键技术/模块** |
| :--- | :--- | :--- | :--- |
| **1. 资产盘点** | 手动梳理供应链相关模块 | **自动化、全量化**的系统画像与 API 目录构建 | `API Introspection`, `Schema Discovery` |
| **2. 上下文构建** | 规则内硬编码 | **多源异构索引**：API文档、SOP、代码、数据字典统一嵌入 | `RAG`, `Knowledge Graph`, `efiagent/core/memory.py` |
| **3. 语义对齐** | 预定义任务类型 | **企业本体与指标DSL**：实现“目标→指标→数据”的自动对齐 | `efiagent/core/ontology.py` |
| **4. 能力封装** | 占位工具函数 | **类型安全的工具注册**与零信任策略封装 | `ToolSpec`, `Security Decorators`, `efiagent/security/zero_trust.py` |
| **5. 智能规划** | 固定DAG分解规则 | **动态规划**：Intent→检索→工具选择→动态生成任务DAG | `Planning Agent as a Router`, `efiagent/agent/planning_agent.py` |
| **6. 安全执行** | 轻量校验 | **前置仿真与灰度发布**：沙盒/影子执行，避免生产事故 | `Simulation Engine`, `Canary Release`, `efiagent/core/task_dag.py` |
| **7. 效果评估** | 手动验证 | **自动化评估与持续学习**：A/B测试、因果推断、策略自动优化 | `A/B Testing Framework`, `efiagent/evolution/evolution_protocol.py` |

### 11.3 v2.0 实施路线图

此计划将作为供应链能力建成后的核心迭代方向。

- **Q1: 基础设施建设**
    - **T1: 资产盘点与上下文管道 (t1, t3)**: 完成核心业务系统（如ERP, CRM）的 API 和数据结构盘点，构建自动化索引管道。
    - **T2: 本体与指标DSL (t2)**: 建立覆盖 1-2 个核心业务域（如销售、库存）的本体与指标 DSL。
    - **T3: 能力注册与安全 (t4, t7)**: 将 20-30 个高频 API 封装为安全工具。

- **Q2: 规划与执行能力增强**
    - **T4: 动态规划器 (t5)**: 升级 `PlanningAgent`，支持基于检索的动态任务规划。
    - **T5: 仿真与安全控制 (t6)**: 实现任务 DAG 的离线仿真与影子执行能力。

- **Q3: 闭环与试点**
    - **T6: 评估与观测 (t8)**: 建立金标任务集（Golden Tasks）和离线评测框架。
    - **T7: 试点场景上线 (t10)**: 选择 1-2 条业务链路（如“销售预测与库存联动”），上线端到端闭环应用。

- **Q4: 平台化与治理**
    - **T8: 治理与版本 (t9)**: 建立 Prompt/Policy/Tool/本体的版本管理与治理流程。
    - **T9: 平台能力开放**: 将通用业务智能能力以平台形式，赋能更多业务部门。

### 11.4 对现有计划的继承与扩展

本 v2.0 计划并非推翻 v1.0，而是其**自然演进和能力泛化**。v1.0 的供应链场景将成为 v2.0 平台的第一个**标杆应用**和**最佳实践验证场**。在 v1.0 中为供应链构建的分解规则、工具和审计流程，将作为 v2.0 **超级上下文**的第一批核心资产被索引和管理，并逐步由动态生成机制所取代。

通过这个扩展，EFIAgent 将从一个项目制交付的工具，转变为一个可持续进化、赋能全企业业务创新的智能基础设施。
