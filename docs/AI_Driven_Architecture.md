# AI 驱动的业务智能：从数据链路到智能闭环

## 1. 核心理念：从“数据驱动”到“AI驱动”

传统的“数据驱动”模式通常是一条线性的、由人工专家主导的链路：

`数据采集 → 指标设计 → 根因分析 → 策略制定 → 自动化执行 → 效果评估`

这条链路的每个环节都高度依赖人的经验和判断，系统之间存在壁垒，导致响应周期长、扩展性差、架构复杂度高。

“AI 驱动”模式旨在通过引入一个“智能决策主体”（即 Agent），将上述线性链路重构为一个动态、自主的闭环，实现“目标导向、自我驱动、持续学习”的业务新范式。

**AI 驱动的能力链路：**

`目标 (Intent) → 数据 (Context) → 智能 (Intelligence) → 执行 (Execution) → 反馈 (Feedback)`

在这个闭环中，AI Agent 贯穿始终，负责理解业务目标、感知上下文、自主决策、安全执行并评估结果，从而显著降低系统集成的复杂性，提升业务的敏捷性和智能化水平。

## 2. 技术实现与逻辑拆解

下面，我们将结合 `EFIAgent` 的核心模块，对这个 AI 驱动的闭环进行技术层面的拆解。

### 2.1 目标 (Intent)：用户意图的结构化理解

-   **核心逻辑**: 将用户以自然语言表达的模糊、高层次的业务目标，转化为机器可理解、可执行的结构化意图。
-   **技术实现**:
    -   **模块**: `efiagent.planner`
    -   **流程**:
        1.  **意图识别**: 使用大型语言模型（LLM）初步解析用户输入，识别其核心指令和目标。
        2.  **槽位填充**: 结合 `efiagent.core.ontology` 中定义的业务本体，从用户输入中提取关键实体、指标和约束条件。
        3.  **歧义澄清**: 当意图不明确或缺少必要参数时，通过 `interactive_planner` 生成一个 `ClarificationTask`，主动向用户提问，寻求必要信息。

-   **代码逻辑示例** (`interactive_planner.py`):
    ```python
    # 用户输入: "我想查询上海地区的最新销售额"
    intent = "我想查询上海地区的最新销售额"

    # 1. 规划器识别到 "查询销售额" 意图，并关联到 "query_sales_metric" 工具。
    # 2. 工具 "query_sales_metric" 需要 "region" 和 "time_range" 两个参数。
    # 3. 规划器从意图中提取出 region="上海"。
    # 4. 发现 "time_range" 参数缺失，生成澄清任务。
    plan = planner.create_plan(intent, tool_registry)
    # plan.tasks -> [ClarificationTask(question="需要哪个时间范围的销售额？(例如：最近一天、最近一周)")]
    ```

### 2.2 数据 (Context)：构建可感知、可行动的“超级上下文”

-   **核心逻辑**: 将企业内部所有与业务相关的静态知识（文档、SOP、数据表结构）和动态能力（API、工具）进行统一的采集、索引和封装，形成一个供 Agent 感知和交互的“世界模型”。
-   **技术实现**:
    -   **模块**: `efiagent.core`
    -   **流程**:
        1.  **资产采集 (`context_collector.py`)**: 通过不同的 `Collector`（如 `ApiSpecCollector`, `MarkdownDocCollector`）从各种数据源自动发现和抽取业务资产。
        2.  **语义建模 (`ontology.py`)**: 使用 `OntologyManager` 定义核心业务实体（如“订单”、“客户”）、指标（如“销售额”）及其关系，为异构数据提供统一的语义层。
        3.  **能力封装 (`tool_registry.py`)**: 将采集到的 API 等能力，通过 `convert_api_asset_to_tools` 转换为标准化的 `ToolSpec`，包含清晰的描述、参数和安全约束。
        4.  **索引与嵌入**: 对所有采集到的资产（文档、工具描述等）进行向量化嵌入，并存入向量数据库，为后续的语义检索提供支持。

### 2.3 智能 (Intelligence)：从意图到可执行计划的生成

-   **核心逻辑**: 这是 Agent 的“大脑”。它根据结构化的意图，在“超级上下文”中检索相关知识和可用工具，并编排出一个最优的、满足约束条件的执行计划（Plan）。
-   **技术实现**:
    -   **模块**: `efiagent.planner` (未来将引入更高级的规划器)
    -   **流程**:
        1.  **相关性检索**: 将用户意图向量化，在向量数据库中检索最相关的知识片段（如“销售额的统计口径说明文档”）和最匹配的工具（如 `query_sales_metric`）。
        2.  **工具选择与参数绑定**: LLM 根据检索到的信息，选择最合适的工具，并尝试从意图和知识片段中填充工具所需参数。
        3.  **任务生成与依赖解析 (`dag_planner.py`)**: 将每一次工具调用定义为一个 `Task`。分析任务之间的逻辑关系（例如，必须先获取用户ID，才能查询该用户的订单），构建一个有向无环图（DAG）。
        4.  **计划生成**: 对任务 DAG 进行拓扑排序，生成一个线性的、可执行的任务序列。

-   **代码逻辑示例** (`dag_planner.py`):
    ```python
    # 用户意图: "帮我查一下张三最近一个月的订单总额"

    # 1. 检索到 "find_user_by_name" 和 "calculate_order_amount" 两个工具。
    # 2. 规划器识别出，必须先执行 find_user_by_name(name="张三") 得到 user_id。
    # 3. 然后才能执行 calculate_order_amount(user_id=..., time_range="last_month")。
    plan = dag_planner.create_plan(intent, registry)
    
    # plan.dag 包含两个节点和一条从 find_user_by_name 到 calculate_order_amount 的边。
    # plan.get_execution_order() -> [Task(find_user_by_name), Task(calculate_order_amount)]
    ```

### 2.4 执行 (Execution)：安全、可控、可观测的自动化操作

-   **核心逻辑**: 将规划器生成的抽象计划，转化为对底层系统（API、数据库）的真实调用。此过程必须是安全、可靠且全程可观测的。
-   **技术实现**:
    -   **模块**: `efiagent.agent.execution_agent` (执行代理), `efiagent.security` (安全模块)
    -   **流程**:
        1.  **任务分发**: `ExecutionAgent` 按顺序从 `Plan` 中获取 `Task`。
        2.  **安全审计与策略执行 (`zero_trust.py`)**: 在执行每个 `Task` 前，检查其 `ToolSpec` 中声明的 `required_permissions`。结合当前操作者的身份和上下文，进行动态的权限校验（RBAC/ABAC）。
        3.  **仿真与灰度 (可选)**: 对于高风险操作，可先在“影子系统”或沙盒环境中执行，验证其影响，再应用到生产环境。
        4.  **实际调用**: 调用工具对应的底层实现（如发送一个 HTTP 请求）。
        5.  **结果捕获与日志**: 记录每次调用的参数、返回结果、耗时、成功或失败状态，形成详细的审计日志。

### 2.5 反馈 (Feedback)：实现效果评估与闭环自学习

-   **核心逻辑**: 对比执行结果和最初的业务目标，评估任务完成的质量，并将评估结果用于指导下一轮的决策和优化，形成一个完整的学习闭环。
-   **技术实现**:
    -   **模块**: `efiagent.agent.audit_agent` (评估代理), `efiagent.core.memory` (记忆模块)
    -   **流程**:
        1.  **效果评估**: `AuditAgent` 分析 `ExecutionAgent` 产生的日志。对于有明确量化目标的任务（如“将用户注册转化率提升5%”），直接对比核心业务指标的变化。对于无法直接量化的任务，可通过与用户的多轮澄清或人工评分来评估。
        2.  **归因分析**: 如果执行结果未达到预期，系统会尝试分析失败原因。是规划错误？工具选择不当？还是工具本身执行失败？
        3.  **知识库更新**: 将成功的“意图-计划-结果”三元组存入 `Memory` 模块，作为未来规划的优质范例（Few-shot examples）。
        4.  **模型/策略优化**: 对于反复出现的规划失败或执行错误，可以触发报警，提示人工介入。在更高级的系统中，这些失败案例可被用于微调（Fine-tuning）规划模型或优化工具描述/安全策略，实现真正的自学习和自适应演化。

通过以上五个环节的紧密协同，一个以 AI 为核心的智能业务闭环得以形成，从而将复杂的业务逻辑和系统交互内化到 Agent 的自主决策流程中，最终实现您所期望的“数据自主理解、指标动态生成、决策智能演化、执行自适应调整、闭环自学习”。
