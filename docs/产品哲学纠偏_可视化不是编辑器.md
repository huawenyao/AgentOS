# 产品哲学纠偏：可视化不是编辑器

## 上一版的根本错误

上一版把 ReactFlow 画布当成了产品的核心——用户拖节点、连线、配参数，本质上做了另一个 n8n / Dify / LangGraph Studio。

这犯了一个底层认知错误：**把"可视化"等同于"可视化编辑器"**。

## 正确的认知

可视化在这个产品中的角色不是让用户"画工作流"，而是：

| 维度 | 错误理解 | 正确理解 |
|------|---------|---------|
| **谁画图** | 用户手动拖拽 | AI根据场景和数据动态生成 |
| **图的作用** | 定义执行流程（配置） | 创意引导、思维辅助（洞察） |
| **交互方式** | 鼠标操作画布 | 自然语言对话 |
| **图的形态** | 固定的DAG流程图 | 根据场景变化：思维导图、决策树、数据流、关系网络... |
| **图何时出现** | 用户打开编辑器 | AI认为需要可视化辅助思考时自动呈现 |

## 新的产品哲学

**对话是主体，可视化是AI的思维外化。**

用户说："帮我分析上个月的客户投诉"

- 错误做法：打开一个空画布，让用户拖一个"数据查询Agent"、拖一个"分析Agent"、连线...
- 正确做法：AI直接开始分析，过程中动态生成可视化——
  - 先出一个投诉分类的树形图（帮用户看到问题全貌）
  - 再出一个趋势时间线（帮用户发现规律）
  - 最后出一个根因关系网络（帮用户理解因果）
  - 用户随时可以对着图说"这个分支展开看看"

**工作流是AI自主规划的，不需要用户画。用户只需要说意图，AI负责拆解、执行、并在过程中用图形帮用户理解正在发生什么。**

## 架构影响

| 组件 | 变化 |
|------|------|
| **前端主界面** | 从6页面Tab布局 → 对话式工作台 + 右侧动态可视化面板 |
| **WorkflowCanvas** | 删除拖拽编辑器 → 改为AI生成的场景图渲染器 |
| **工作流创建** | 从用户手动CRUD → AI根据意图自动生成工作流 |
| **可视化组件** | 从固定DAG编辑器 → 多形态动态图形（思维导图/流程图/关系网/决策树/数据图表） |
| **后端API** | 新增 `/api/sessions` 对话式任务接口 + 可视化生成接口 |
