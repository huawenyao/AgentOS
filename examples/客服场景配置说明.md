# 智能客服场景配置说明

## 概述

本文档详细说明了基于EFIAgent 2.0架构的智能客服系统配置，包含完整的Agent配置、工作流配置和部署方案。该配置展示了如何构建一个生产级的智能客服系统，实现从客户请求接收到问题解决的全流程自动化。

## 架构设计

### 三层架构模型

```
工作流层 (Workflow Layer)
    ↓ 编排协调
Agent层 (Agent Layer)  
    ↓ 组合调用
能力层 (Capability Layer)
```

### 核心组件

1. **能力模块 (Capabilities)**: 提供原子化的智能能力
2. **Agent模块 (Agents)**: 组合能力形成专业智能体
3. **工作流模块 (Workflows)**: 协调多个Agent完成复杂业务流程

## Agent配置详解

### 1. 智能客服助手 (customer_service_agent)

**功能定位**: 核心客服Agent，负责与客户直接交互

**核心能力**:
- **自然语言理解**: 基于BERT模型的中文理解能力
- **意图识别**: 支持6大类客服意图识别
- **知识库查询**: 语义搜索知识库内容
- **响应生成**: 个性化、专业化回复生成
- **情感分析**: 实时监控客户情绪状态
- **多轮对话管理**: 维护对话上下文和状态

**配置要点**:
```json
{
  "maxConcurrentSessions": 100,  // 最大并发会话数
  "responseTimeout": 5000,       // 响应超时时间(ms)
  "fallbackStrategy": "human_handover", // 兜底策略
  "escalationRules": {           // 升级规则
    "sentiment_threshold": -0.7,  // 情感阈值
    "unresolved_turns": 5,       // 未解决轮次
    "vip_customer": true         // VIP客户自动升级
  }
}
```

### 2. 请求分类专家 (categorization_agent)

**功能定位**: 专门负责分析和分类客户请求

**核心能力**:
- **请求分析**: 深度分析请求内容，提取关键信息
- **类别分类**: 支持多标签分类，6大业务类别

**应用场景**:
- 新请求的自动分类
- 复杂请求的多维度分析
- 为后续路由提供决策依据

### 3. 智能路由分配器 (routing_agent)

**功能定位**: 根据请求特征智能分配处理资源

**核心能力**:
- **队列管理**: 加权轮询负载均衡
- **客服匹配**: 基于技能、语言、工作负载的智能匹配

**路由策略**:
- 技能匹配优先
- 工作负载均衡
- VIP客户特殊路由
- 语言偏好考虑

### 4. 通知服务专家 (notification_agent)

**功能定位**: 负责多渠道客户通知

**核心能力**:
- **多渠道通知**: 支持邮件、短信、推送、应用内通知
- **状态跟踪**: 实时更新处理状态，记录历史轨迹

## 工作流配置详解

### 智能客服处理流程 (customer_service_workflow)

#### 流程概述

该工作流实现了完整的客服请求处理自动化，包含以下关键阶段：

1. **请求接收阶段**: 接收、验证、预处理
2. **分析分类阶段**: 内容分析、意图识别、类别分类
3. **优先级评估阶段**: 多维度优先级评估
4. **路由决策阶段**: 智能路由分配
5. **处理执行阶段**: 自动回复或人工分配
6. **质量保证阶段**: 质量检查、跟进安排
7. **异常处理阶段**: 升级处理、错误恢复

#### 关键节点说明

**条件判断节点 - auto_response_check**:
```json
{
  "condition": "${categorization.output.confidence} > 0.9 AND ${categorization.output.category} in ['faq', 'simple_inquiry']",
  "true_path": "auto_response",
  "false_path": "human_assignment"
}
```

**升级处理逻辑**:
- 紧急请求自动升级
- 质量不达标触发升级
- VIP客户特殊处理路径

#### 触发器配置

**事件触发器**:
```json
{
  "type": "event",
  "event": "customer_message_received",
  "condition": "message.channel in ['web', 'mobile', 'email']"
}
```

**定时触发器**:
```json
{
  "type": "schedule",
  "cron": "0 */2 * * *",
  "description": "每2小时检查待跟进的请求"
}
```

#### SLA配置

**响应时间要求**:
- 紧急: 5分钟
- 高优先级: 15分钟  
- 中等优先级: 1小时
- 低优先级: 4小时

**解决时间要求**:
- 紧急: 2小时
- 高优先级: 8小时
- 中等优先级: 24小时
- 低优先级: 72小时

**质量目标**:
- 客户满意度: 4.5/5.0
- 首次解决率: 80%

## 使用指南

### 1. 部署步骤

1. **环境准备**:
   ```bash
   # 安装依赖
   npm install
   pip install -r requirements.txt
   
   # 配置环境变量
   cp .env.example .env
   # 编辑.env文件，配置数据库、Redis等连接信息
   ```

2. **数据库初始化**:
   ```bash
   # 创建数据库表
   python scripts/init_database.py
   
   # 导入知识库数据
   python scripts/import_knowledge_base.py
   ```

3. **启动服务**:
   ```bash
   # 启动后端服务
   cd backend && npm start
   
   # 启动前端界面
   cd examples/agent_designer_ui && npm start
   ```

### 2. 配置导入

1. **导入Agent配置**:
   - 在Agent管理界面选择"导入配置"
   - 上传`customer_service_scenario.json`中的agents部分
   - 验证配置并保存

2. **导入工作流配置**:
   - 在工作流设计器中选择"导入工作流"
   - 上传workflows部分配置
   - 检查节点连接和参数配置

3. **配置能力模块**:
   - 在能力库中注册自定义能力
   - 配置能力参数和依赖关系
   - 测试能力模块功能

### 3. 测试验证

## 扩展开发

```python
# 示例：自定义情感分析能力
class CustomSentimentAnalysis(BaseCapability):
    def __init__(self, config):
        super().__init__(config)
        self.model = load_sentiment_model()
    
    def execute(self, input_data):
        text = input_data.get('text')
        sentiment = self.model.predict(text)
        return {
            'sentiment': sentiment,
            'confidence': sentiment.confidence
        }
```
